# ระบบบริหารงานขนส่ง — บริษัท เทียมเทพ ขนส่ง จำกัด

เว็บแอปสำหรับบันทึกงานขนส่งประจำวัน คำนวณต้นทุน และสรุปกำไรขาดทุน
แทนที่ไฟล์ Excel เดิม โดยยกฐานข้อมูลและสูตรคำนวณทั้งหมดมาไว้ในระบบเดียว

## ติดตั้งบน CHUEY-Server

ต้องมี **Node.js 20 ขึ้นไป** และ **Docker** (สำหรับฐานข้อมูล)

### วิธีง่าย (Mac) — ดับเบิลคลิกไฟล์เดียว

1. ติดตั้ง [Docker Desktop](https://www.docker.com/products/docker-desktop/) แล้วเปิดโปรแกรมทิ้งไว้
2. ติดตั้ง [Node.js LTS](https://nodejs.org)
3. ดับเบิลคลิก **`install-mac.command`** ในโฟลเดอร์นี้

สคริปต์จะตั้งรหัสผ่านฐานข้อมูลแบบสุ่ม เปิดฐานข้อมูล สร้างตาราง นำเข้าข้อมูล
ตั้งให้ระบบเปิดเองอัตโนมัติตอนเข้าเครื่อง แล้วเปิดเว็บให้เลย —
หน้าเว็บที่เปิดขึ้นมาครั้งแรกจะให้**ตั้งบัญชีผู้ดูแลระบบเอง** (บัญชีแรกของระบบ
เป็นผู้ดูแลอัตโนมัติ ไม่ต้องรออนุมัติ)

ให้เปิดเองได้แม้เครื่องรีสตาร์ท ต้องตั้งเพิ่ม 2 อย่าง:

- Docker Desktop → Settings → General → เปิด **Start Docker Desktop when you sign in**
- System Settings → Users & Groups → ตั้ง **Automatically log in as** เป็นบัญชีที่ติดตั้ง
  (launchd แบบผู้ใช้จะเริ่มงานหลังล็อกอินเข้าเครื่อง)

คำสั่งที่ใช้บ่อย:

```bash
launchctl unload ~/Library/LaunchAgents/com.tiamthep.server.plist   # ปิดระบบ
launchctl load   ~/Library/LaunchAgents/com.tiamthep.server.plist   # เปิดระบบ
tail -f server.log                                                  # ดูบันทึกการทำงาน
```

ถ้าดับเบิลคลิกแล้วขึ้นว่าเปิดไม่ได้ ให้คลิกขวาที่ไฟล์ → Open ครั้งแรกครั้งเดียว
หรือรัน `chmod +x install-mac.command` ใน Terminal ก่อน

### อัปเดตระบบเป็นเวอร์ชันใหม่ (Mac)

ดับเบิลคลิก **`update-mac.command`** — ดึงโค้ดล่าสุด ปรับโครงสร้างฐานข้อมูล
build ใหม่ แล้วรีสตาร์ทระบบให้เอง **ข้อมูลที่บันทึกไว้อยู่ครบ**

> ⚠ เครื่องที่มีข้อมูลจริงแล้ว **ห้ามรัน `npm run setup` ซ้ำ** — คำสั่งนั้น
> ล้างและนำเข้าข้อมูลใหม่ทั้งหมด ใช้เฉพาะติดตั้งครั้งแรกเท่านั้น
> การอัปเดตใช้ `update-mac.command` (หรือ `npm run db:migrate`) เสมอ
> และควร `npm run db:backup` ก่อนอัปเดตทุกครั้ง

### วิธีติดตั้งเอง (ทุกระบบ)

```bash
# 1. ตั้งค่า
cp .env.example .env
nano .env                 # ตั้ง POSTGRES_PASSWORD และ DATABASE_URL ให้ตรงกัน

# 2. เปิดฐานข้อมูล (พร้อมตัวสำรองข้อมูลอัตโนมัติ)
docker compose up -d

# 3. ติดตั้งและสร้างตาราง + นำเข้าข้อมูลจากไฟล์ Excel เดิม
npm install
npm run setup

# 4. เปิดใช้งาน
npm run build
npm start                 # เปิดที่ http://localhost:3000
```

เปิดเว็บครั้งแรกระบบจะพาไปหน้า **ตั้งค่าครั้งแรก** ให้สร้างบัญชีผู้ดูแลเอง —
บัญชีแรกของระบบเป็นผู้ดูแลและเข้าใช้งานได้ทันที
(อยากสร้างจาก command line แทน ให้ตั้ง `ADMIN_USERNAME` / `ADMIN_PASSWORD_INIT`
ใน `.env` ก่อนรัน `npm run setup` — จะพิมพ์รหัสออกมาครั้งเดียว)

ลืมรหัสผ่านผู้ดูแล หรืออยากเริ่มตั้งค่าผู้ใช้ใหม่ทั้งหมด:

```bash
npm run reset:users -- --yes    # ลบเฉพาะบัญชี — ข้อมูลงานและบันทึกเดิมอยู่ครบ
```

เริ่มจากฐานข้อมูลจริงล้วน ไม่เอาข้อมูลตัวอย่าง:

```bash
npm run db:seed -- --no-demo
```

ให้เครื่องอื่นในออฟฟิศเข้าใช้ได้ — เปิด port 3000 ที่ firewall แล้วเข้าที่
`http://<ชื่อเครื่องหรือ IP ของ CHUEY-Server>:3000`

เปิดหน้า **คู่มือการใช้งาน** ในเมนูซ้ายก่อนเริ่มใช้จริง

### ให้ระบบเปิดเองทุกครั้งที่เครื่องบูต

**Mac** — `install-mac.command` ตั้งให้แล้วอัตโนมัติ (LaunchAgent
`com.tiamthep.server` เรียก `scripts/mac/run-server.sh` ซึ่งรอ Docker →
เปิดฐานข้อมูล → เปิดเว็บ) ดูหัวข้อ "วิธีง่าย (Mac)" ด้านบน

**Linux** — ใช้ systemd:

```ini
# /etc/systemd/system/tiamthep.service
[Unit]
Description=ระบบบริหารงานขนส่ง เทียมเทพ
After=network.target docker.service

[Service]
Type=simple
User=tiamthep
WorkingDirectory=/opt/tiamthep
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=10
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now tiamthep
```

## ฐานข้อมูลเก็บที่ไหน

ฐานข้อมูลคือ **PostgreSQL 16** ที่รันบน CHUEY-Server — ข้อมูลอยู่ใน Docker volume
ชื่อ `tiamthep-pgdata` บนดิสก์ของเครื่องนั้น ไม่ได้อยู่ในคลาวด์และไม่ได้อยู่ใน container
(ลบ/สร้าง container ใหม่ได้โดยข้อมูลไม่หาย)

ดูที่อยู่จริงบนดิสก์:

```bash
docker volume inspect tiamthep-pgdata --format '{{.Mountpoint}}'
```

ค่าเริ่มต้นเปิดพอร์ตเฉพาะ `127.0.0.1:5432` — เครื่องอื่นต่อฐานข้อมูลตรงไม่ได้
ต้องผ่านเว็บเท่านั้น ถ้าจำเป็นต้องให้เครื่องอื่นต่อตรง ให้แก้ `docker-compose.yml`
เป็น `"5432:5432"` แล้วตั้ง firewall ให้รัดกุม

### การสำรองข้อมูล

ตัวสำรองทำงานอัตโนมัติทุกวันเวลา 02:00 เก็บย้อนหลัง 30 วัน ลงโฟลเดอร์ `backup/`

```bash
npm run db:backup     # สำรองเองทันที (ทำก่อนอัปเดตระบบทุกครั้ง)
```

กู้คืน:

```bash
gunzip -c backup/tiamthep-YYYYMMDD-HHMMSS.sql.gz | psql "postgresql://tiamthep:รหัสผ่าน@127.0.0.1:5432/tiamthep"
```

ไฟล์สำรองอยู่บนเครื่องเดียวกับฐานข้อมูล — **ควรก๊อปออกไปเก็บนอกเครื่องด้วย**
(external drive หรือ NAS) เผื่อดิสก์เสีย

### แก้โครงสร้างฐานข้อมูล

ใช้ migration เสมอ เพื่อให้มีประวัติและย้อนกลับได้:

```bash
npx prisma migrate dev --name อธิบายสิ่งที่แก้    # ตอนพัฒนา
npm run db:migrate                              # ตอนติดตั้งบนเซิร์ฟเวอร์จริง
```

อย่าใช้ `prisma db push` กับฐานข้อมูลจริง

ตั้งค่าอื่นๆ ดูที่ `.env.example`

## ผู้ใช้งานและสิทธิ์

ทุกคนต้องเข้าระบบด้วยบัญชีของตัวเอง — ไม่มีหน้าไหนเปิดดูได้โดยไม่ล็อกอิน

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| ผู้ดูแลระบบ (สูงสุด 4 คน) | ทุกอย่าง รวมถึงอนุมัติผู้ใช้ จัดการทะเบียนพนักงาน ตั้งค่าระบบ และดูบันทึกการเข้าระบบ |
| พนักงาน | บันทึกข้อมูลและดูรายงาน แต่จัดการผู้ใช้ไม่ได้ |
| ดูอย่างเดียว | เปิดดูได้อย่างเดียว บันทึกหรือแก้ไขไม่ได้ |

**ผู้ดูแลระบบมีได้ไม่เกิน 4 คน** (นโยบายบริษัท) — ระบบไม่ยอมให้อนุมัติหรือ
เปลี่ยนสิทธิ์ใครเป็นผู้ดูแลเกินโควตา ต้องถอดสิทธิ์คนเดิมออกก่อน

**สมัครได้เฉพาะพนักงานบริษัท** — หน้าสมัครตรวจชื่อ-นามสกุลกับ
*ทะเบียนพนักงาน* ก่อน ไม่พบชื่อ = ปุ่มสมัครกดไม่ได้ และ **1 รายชื่อสร้างได้
1 บัญชีเท่านั้น** ผู้ดูแลจัดการรายชื่อที่หน้า *ผู้ดูแลระบบ → ทะเบียนพนักงาน*
(ชื่อ พขร. ทั้งหมดถูกเติมให้อัตโนมัติตอนติดตั้ง พนักงานออฟฟิศเพิ่มเองได้)
พนักงานลาออกให้กดปิดใช้งานชื่อในทะเบียน และระงับบัญชีที่หน้าจัดการผู้ใช้งาน

**การสมัครต้องรออนุมัติ** — ผ่านการตรวจชื่อแล้ว บัญชียังอยู่ในสถานะ
&laquo;รออนุมัติ&raquo; เข้าระบบไม่ได้จนกว่าผู้ดูแลจะอนุมัติและเลือกสิทธิ์ให้ที่หน้า
*ผู้ดูแลระบบ → จัดการผู้ใช้งาน* (เมนูจะขึ้นตัวเลขสีส้มบอกจำนวนคำขอที่ค้างอยู่)

**บันทึกการเข้าระบบ** เก็บทุกเหตุการณ์ — เข้าระบบสำเร็จ/ไม่สำเร็จพร้อมเหตุผล ออกจากระบบ
สมัคร อนุมัติ ปฏิเสธ ระงับ เปลี่ยนสิทธิ์ และเปลี่ยนรหัสผ่าน พร้อมวันเวลา IP และอุปกรณ์
บันทึกนี้แก้ไขหรือลบจากหน้าเว็บไม่ได้ เพื่อให้ใช้ตรวจสอบย้อนหลังได้จริง

วิธีป้องกันที่ใส่ไว้:

- รหัสผ่านเก็บเป็น **scrypt hash** พร้อม salt รายคน — ฐานข้อมูลรั่วก็อ่านรหัสจริงไม่ได้
- เซสชันเก็บเฉพาะ **hash ของ token** ส่วน token จริงอยู่ใน cookie แบบ httpOnly เท่านั้น
- ใส่รหัสผิดติดกัน **5 ครั้ง ล็อกบัญชี 15 นาที** และหน่วงเวลาตอบทุกครั้งที่ผิด
- ข้อความตอนล็อกอินผิดเหมือนกันหมด ไม่บอกใบ้ว่าชื่อผู้ใช้ไหนมีอยู่จริง
- กด **ระงับ** แล้วเซสชันที่เปิดค้างอยู่ทุกเครื่องถูกตัดทันที
- ผู้ดูแลระบบคนสุดท้ายถูกถอดสิทธิ์หรือระงับไม่ได้ — กันล็อกตัวเองออกจากระบบ

พนักงานลาออกให้กด **ระงับ** อย่าลบบัญชี เพื่อให้ประวัติการทำงานยังตรวจสอบได้

## สิ่งที่ระบบทำให้

### บันทึกประจำวัน

| หน้า | ทำอะไร |
|---|---|
| บันทึกงานขนส่ง | 1 แถว = 1 ขา · กรอกแค่ทะเบียนกับเส้นทาง ระบบหา พขร. ระยะทาง KPI น้ำมัน เบี้ยเลี้ยง และค่าบรรทุกให้เอง · มีปุ่มสร้างขากลับในคลิกเดียว |
| เงินเดินทาง / ค่าทางด่วน | เงินที่จ่าย พขร. ก่อนออกงาน และค่าทางด่วนที่ พขร. สำรองจ่าย |
| ค่าใช้จ่าย | ค่ายาง ซ่อมบำรุง ค่าปรับ ฯลฯ (ค่าน้ำมันไม่ต้องกรอก ระบบดึงให้) |
| การเติมน้ำมัน | อัปโหลดไฟล์ที่ export จากระบบน้ำมัน (ปั๊มบริษัท R-005 และ Fleet Card) · ตรวจสอบก่อนบันทึกได้ · นำเข้าซ้ำไม่เกิดข้อมูลซ้ำ |
| งานจากไลน์ (ชีตสั่งงาน) | ดึงงานจากชีตสั่งงานคนขับ (ไลน์บอทแจ้งงานล่วงหน้า 17:00 เก็บตก 18:00 + OCR รูปตั๋ว) เข้ามาเป็นงานขนส่ง — เฉพาะแถวที่ออฟฟิศตรวจและ «ยืนยัน» แล้ว · ดึงซ้ำไม่เกิดงานซ้ำ · วิธีติดตั้งทั้งระบบอยู่ใน [`line-bot/README.md`](./line-bot/README.md) |

### รายงาน

1. **งบกำไรขาดทุนของกิจการ** — รายเดือน พร้อมกราฟแนวโน้ม 12 เดือนย้อนหลัง
2. **กำไรขาดทุนแยกตามทะเบียนรถ** — เลือกช่วงวันที่เองได้
3. **กำไรขาดทุนแยกตาม พขร.**
4. **รายงานรายได้** — แยกตามลูกค้า / ทะเบียน / พขร. / ประเภทรถ
5. **รายงานค่าใช้จ่าย** — แยกตามประเภท / ทะเบียน / พขร. / ผู้ให้บริการ พร้อมกราฟ
6. **สรุปเบี้ยเลี้ยง พขร.** — รายงวด (1-15 และ 16-สิ้นเดือน) พิมพ์แนบเงินเดือนได้
7. **เงินพิเศษค่าน้ำมัน** — จับคู่ขาไป-ขากลับให้อัตโนมัติ
8. **จ่ายเงินรถร่วม** — แจกแจงงาน น้ำมัน ค่าใช้จ่ายจ่ายแทน และยอดสุทธิ

ทุกรายงานพิมพ์เป็น PDF ได้ (ปุ่มพิมพ์จะซ่อนเมนูและปุ่มให้เอง)

### ฐานข้อมูล

ข้อมูลรถ (พร้อมแจ้งเตือนภาษี/พ.ร.บ./ประกันใกล้หมดอายุ และอายุรถ) ·
พนักงานขับรถ (พร้อมแจ้งเตือนใบขับขี่) · จับคู่รถ+พขร. แบบมีวันที่มีผล ·
ลูกค้า · เส้นทาง+ระยะทาง+เบี้ยเลี้ยง+ราคา · ราคาน้ำมันอ้างอิง · รถร่วม

### คลังอะไหล่

รายการสินค้า · รับเข้า/เบิกใช้สต็อก · ใบวางบิลอู่ (ตรวจว่าอู่เรียกเก็บตรงกับที่เบิกจริง) ·
สรุปคงเหลือพร้อมเตือนจุดสั่งซื้อ

**ทะเบียนยาง/แบตเตอรี่รายชิ้น** — ติดตามได้ว่ายางเส้นไหนอยู่รถคันไหน ตำแหน่งอะไร
ถอดออกเมื่อไหร่ ดอกยางเหลือเท่าไหร่ตอนถอด และขายไปหรือยัง

สถานะคำนวณจากรายการเบิกใช้จริงเท่านั้น พิมพ์ทับเองไม่ได้ —
ปิดช่องทางที่ของเก่าจะหายไปโดยไม่มีใครรู้:

```
อยู่ในสต็อก → ติดตั้งอยู่ (รถ + ตำแหน่งล้อ) → ถอดออกแล้ว รอขาย → ขายแล้ว / ทิ้ง
```

ต้นทุนอะไหล่ที่เบิกไปเข้ารายงานกำไรขาดทุนของรถคันนั้นอัตโนมัติ

## เรื่องที่ออกแบบไว้เป็นพิเศษ

### 1. เบี้ยเลี้ยง ระยะทาง ราคาลูกค้า และราคารถร่วม อยู่ที่เดียวกัน

หน้า **เส้นทาง ระยะทาง ราคา** รวมข้อมูล 4 ชุดที่เดิมแยกกันอยู่ 4 sheet
ไว้ในแถวเดียวกัน — 1 แถว = 1 เส้นทาง ต่อ 1 ประเภทรถ
เพราะทั้งสี่อย่างผูกกับ "เส้นทาง + ประเภทรถ" เหมือนกันหมด

ระยะทางกรอกเป็น **ขาเดียว** เสมอ ขากลับต้องเพิ่มเป็นอีกแถว เพื่อกันการกรอกผิดเป็นไป-กลับ

การตั้งราคา 22 ช่วงราคาน้ำมัน × 2 ชุด (ลูกค้า/รถร่วม) มีเครื่องมือช่วย:
กรอกราคาช่วงเดียวแล้วกด "เติมให้ทุกช่วง" ระบบไล่ราคาขั้นบันไดให้ หรือคัดลอกทั้งชุดจากเส้นทางอื่น

### 2. เกณฑ์ราคาน้ำมันของลูกค้า ตั้งเป็นสูตรได้เอง

ลูกค้าแต่ละรายตกลงวิธีคิดราคาน้ำมันไว้ไม่เหมือนกัน ระบบจึงเก็บเป็น "สูตร" ที่แก้ได้
ไม่ใช่ตัวเลือกตายตัว — เพิ่มแบบใหม่ได้เองที่หน้า *ตั้งค่า → เกณฑ์ราคาน้ำมันลูกค้า*

| ชนิดสูตร | ใช้กับ |
|---|---|
| `SHIP_DATE` | ราคา ณ วันที่ขนจริง |
| `DAY_OF_MONTH` | ราคาวันที่ N ของเดือน (วันที่ 1, วันที่ 25, …) |
| `SEMI_MONTHLY` | วันที่ 1-15 ใช้ราคาวันที่ 1 / วันที่ 16 เป็นต้นไปใช้ราคาวันที่ 16 |
| `AVERAGE` | เฉลี่ยช่วง `startDay`→`endDay` · ถ้า start > end คือคาบข้ามเดือน (16→15, 20→19) · `monthOffset` = ถอยหลังกี่เดือน |

ครอบคลุมทุกแบบที่บริษัทใช้อยู่: ราคาวันที่ 1 · ราคาวันที่ 25 · วันที่ 1 และ 16 ·
เฉลี่ย 16-15 ใช้เดือนถัดไป · เฉลี่ย 1-31 เดือนเดียวกัน · เฉลี่ย 20-19 ใช้เดือนถัดไป · ราคาวันขนส่ง

ราคาของวันที่ไม่มีประกาศ = ราคาประกาศล่าสุดก่อนหน้า จึงกรอกเฉพาะวันที่ราคาเปลี่ยนก็พอ

### 3. เงินพิเศษค่าน้ำมัน ไม่ต้องจับคู่เอง

เดิมต้องนั่งดูตารางว่า "ขาไป A + ขากลับ B = น้ำมัน X" แล้วจับคู่กับที่เติมจริงเอง
ตรวจสอบย้อนหลังไม่ได้

ระบบใช้ **รหัสรอบ** แทน: ทุกขาที่อยู่รอบเดียวกันใช้รหัสเดียวกัน
เป้าหมายน้ำมันของรอบ = ผลรวมของ (ระยะทาง ÷ อัตราสิ้นเปลืองเป้าหมาย) ของทุกขาในรอบ
แล้วเทียบกับลิตรที่เติมจริงในวันจบรอบ

```
เงินซื้อคืน = (เป้าหมายรอบ − ลิตรที่เติมจริง) × อัตราซื้อคืน
ใช้เกินเป้า → ได้ 0 บาท แต่ไม่หักเงิน
```

รายงานแสดงเส้นทางทุกขาในรอบพร้อมเป้าหมายรายขา จึงตรวจย้อนกลับได้ทุกตัวเลข
ถ้าเติมคนละวันกับวันจบรอบ แก้ลิตรจริงในตารางได้ทันที

### 4. ตัวเลขทุกรายงานมาจากเครื่องคำนวณตัวเดียว

`src/lib/calc.ts` คำนวณรายขาเพียงที่เดียว แล้วรายงานทุกหน้าใช้ผลลัพธ์ก้อนเดียวกัน
จึงไม่มีทางที่ตัวเลขสองหน้าจะขัดกันเอง

มีสคริปต์ตรวจความสอดคล้องให้รันได้ตลอด:

```bash
npx tsx scripts/verify-consistency.ts   # ตรวจว่ารายงานทุกหน้าตัวเลขตรงกัน
npx tsx scripts/verify-calc.ts          # ดูรายละเอียดการคำนวณทีละขั้น
```

ตรวจว่า: รายงานค่าใช้จ่าย (ทั้ง 4 มุมมอง) รวมเท่ากับต้นทุนในงบกำไรขาดทุน ·
รายงานรายได้ (ทั้ง 4 มุมมอง) รวมเท่ากับรายได้ในงบ · กำไรรายคันรวมกับค่าใช้จ่ายส่วนกลาง
เท่ากับกำไรสุทธิ · เบี้ยเลี้ยงงวด 1 + งวด 2 เท่ากับทั้งเดือน

### 5. รถร่วมไม่ถูกนับต้นทุนซ้ำ

ค่าน้ำมันและค่าใช้จ่ายที่บริษัทออกแทนรถร่วม จะถูกหักคืนตอนจ่ายค่าจ้างอยู่แล้ว
ระบบจึงไม่นับซ้ำเป็นต้นทุนบริษัท — ต้นทุนของงานรถร่วมคือ "ค่าจ้างรถร่วม" ก้อนเดียว
(ถ้านับซ้ำ ต้นทุนจะสูงเกินจริงและกำไรจะดูต่ำกว่าความเป็นจริง)

### 6. บอกทันทีเมื่อข้อมูลยังไม่ครบ

ทุกขาที่คำนวณไม่ได้จะถูกทำเครื่องหมายพร้อมบอกสาเหตุ (ไม่พบเส้นทาง / ยังไม่ตั้งราคาช่วงนี้ /
ไม่พบการจับคู่ พขร. / คิดต่อตันแต่ไม่ได้กรอกน้ำหนัก) แสดงทั้งที่หน้าหลักและหน้าบันทึกงาน
เพื่อไม่ให้เผลอเชื่อรายงานที่ตัวเลขยังไม่ครบ

## หมายเหตุเรื่องข้อมูลที่นำเข้ามา

- **วันที่แบบ พ.ศ.** ในไฟล์เดิม (เช่น `31/03/2570`) ถูกแปลงเป็น ค.ศ. อัตโนมัติ
- **ทะเบียนรถ** ในไฟล์เดิมเขียนไม่เหมือนกันทุกที่ (`70-1779` กับ `70-1779 ลบ.`)
  ระบบตัดคำต่อท้ายให้เหลือเลขทะเบียนล้วน เพื่อให้จับคู่กันได้
- **ลูกค้าที่ไม่มีรหัสย่อ** ในไฟล์เดิม ระบบตั้งรหัสให้ชั่วคราวเป็น `C001`, `C002`, …
  ควรเข้าไปแก้ให้เป็นรหัสจริงที่หน้าข้อมูลลูกค้า
- **เส้นทางในไฟล์เดิมมี 4 เส้นทาง** และเป็นประเภทรถ `รถพ่วง` ซึ่งไม่ตรงกับประเภทรถจริง
  ในทะเบียนรถ (`รถดั๊ม`, `หัวลาก`, …) — ต้องเพิ่มเส้นทางจริงให้ครบก่อนใช้งาน
  ไม่งั้นงานจะขึ้นเตือนว่า "ไม่พบเส้นทาง"
- **พขร. บางคน** ที่มีในตารางจับคู่รถแต่ไม่มีในทะเบียนพนักงาน ถูกสร้างให้เป็น `(รอกรอกชื่อ)`
