# ระบบบริหารงานขนส่ง — บริษัท เทียมเทพ ขนส่ง จำกัด

เว็บแอปสำหรับบันทึกงานขนส่งประจำวัน คำนวณต้นทุน และสรุปกำไรขาดทุน
แทนที่ไฟล์ Excel เดิม โดยยกฐานข้อมูลและสูตรคำนวณทั้งหมดมาไว้ในระบบเดียว

## เริ่มใช้งาน

ต้องมี **Node.js 20 ขึ้นไป**

```bash
npm install      # ติดตั้ง
npm run setup    # สร้างฐานข้อมูล + นำเข้าข้อมูลจากไฟล์ Excel เดิม + ข้อมูลตัวอย่าง
npm run dev      # เปิดใช้งานที่ http://localhost:3000
```

เริ่มจากฐานข้อมูลจริงล้วน ไม่เอาข้อมูลตัวอย่าง:

```bash
npm run db:seed -- --no-demo
```

ใช้งานจริงบนเซิร์ฟเวอร์:

```bash
npm run build
npm start
```

เปิดหน้า **คู่มือการใช้งาน** ในเมนูซ้ายก่อนเริ่มใช้จริง

## ฐานข้อมูล

ค่าเริ่มต้นคือ **SQLite** — ทั้งระบบอยู่ในไฟล์เดียว (`prisma/dev.db`)
สำรองข้อมูล = ก๊อปไฟล์นั้นเก็บไว้ ย้ายเครื่อง = ก๊อปไฟล์ไปวาง

ถ้าต่อไปต้องการให้หลายคนใช้พร้อมกันจากหลายเครื่อง ให้ย้ายไป PostgreSQL:

1. แก้ `provider` ใน `prisma/schema.prisma` เป็น `"postgresql"`
2. ตั้ง `DATABASE_URL` ใน `.env` ให้ชี้ไปที่ฐานข้อมูล
3. รัน `npx prisma db push` แล้ว `npm run db:seed`

ตั้งค่าอื่นๆ ดูที่ `.env.example`

## สิ่งที่ระบบทำให้

### บันทึกประจำวัน

| หน้า | ทำอะไร |
|---|---|
| บันทึกงานขนส่ง | 1 แถว = 1 ขา · กรอกแค่ทะเบียนกับเส้นทาง ระบบหา พขร. ระยะทาง KPI น้ำมัน เบี้ยเลี้ยง และค่าบรรทุกให้เอง · มีปุ่มสร้างขากลับในคลิกเดียว |
| เงินเดินทาง / ค่าทางด่วน | เงินที่จ่าย พขร. ก่อนออกงาน และค่าทางด่วนที่ พขร. สำรองจ่าย |
| ค่าใช้จ่าย | ค่ายาง ซ่อมบำรุง ค่าปรับ ฯลฯ (ค่าน้ำมันไม่ต้องกรอก ระบบดึงให้) |
| การเติมน้ำมัน | อัปโหลดไฟล์ที่ export จากระบบน้ำมัน (ปั๊มบริษัท R-005 และ Fleet Card) · ตรวจสอบก่อนบันทึกได้ · นำเข้าซ้ำไม่เกิดข้อมูลซ้ำ |

### รายงาน

1. **งบกำไรขาดทุนของกิจการ** — รายเดือน พร้อมกราฟแนวโน้ม 12 เดือนย้อนหลัง
2. **กำไรขาดทุนแยกตามทะเบียนรถ** — เลือกช่วงวันที่เองได้
3. **กำไรขาดทุนแยกตาม พขร.**
4. **รายงานรายได้** — แยกตามลูกค้า / ทะเบียน / พขร. / ประเภทรถ
5. **รายงานค่าใช้จ่าย** — แยกตามประเภท / ทะเบียน / พขร. / ผู้ให้บริการ พร้อมกราฟ
6. **สรุปเบี้ยเลี้ยง พขร.** — รายงวด (1-15 และ 16-สิ้นเดือน) พิมพ์แนบเงินเดือนได้
7. **เงินพิเศษค่าน้ำมัน** — จับคู่ขาไป-ขากลับให้อัตโนมัติ
8. **จ่ายเงินรถร่วม** — แจกแจงงาน น้ำมัน ค่าใช้จ่ายจ่ายแทน และยอดสุทธิ

ทุกรายงานพิมพ์เป็น PDF ได้ (ปุ่มพิมพ์จะซ่อนเมนูและปุ่มให้เอง)

### ฐานข้อมูล

ข้อมูลรถ (พร้อมแจ้งเตือนภาษี/พ.ร.บ./ประกันใกล้หมดอายุ และอายุรถ) ·
พนักงานขับรถ (พร้อมแจ้งเตือนใบขับขี่) · จับคู่รถ+พขร. แบบมีวันที่มีผล ·
ลูกค้า · เส้นทาง+ระยะทาง+เบี้ยเลี้ยง+ราคา · ราคาน้ำมันอ้างอิง · รถร่วม

### คลังอะไหล่

รายการสินค้า · รับเข้า/เบิกใช้สต็อก · ใบวางบิลอู่ (ตรวจว่าอู่เรียกเก็บตรงกับที่เบิกจริง) ·
สรุปคงเหลือพร้อมเตือนจุดสั่งซื้อ

**ทะเบียนยาง/แบตเตอรี่รายชิ้น** — ติดตามได้ว่ายางเส้นไหนอยู่รถคันไหน ตำแหน่งอะไร
ถอดออกเมื่อไหร่ ดอกยางเหลือเท่าไหร่ตอนถอด และขายไปหรือยัง

สถานะคำนวณจากรายการเบิกใช้จริงเท่านั้น พิมพ์ทับเองไม่ได้ —
ปิดช่องทางที่ของเก่าจะหายไปโดยไม่มีใครรู้:

```
อยู่ในสต็อก → ติดตั้งอยู่ (รถ + ตำแหน่งล้อ) → ถอดออกแล้ว รอขาย → ขายแล้ว / ทิ้ง
```

ต้นทุนอะไหล่ที่เบิกไปเข้ารายงานกำไรขาดทุนของรถคันนั้นอัตโนมัติ

## เรื่องที่ออกแบบไว้เป็นพิเศษ

### 1. เบี้ยเลี้ยง ระยะทาง ราคาลูกค้า และราคารถร่วม อยู่ที่เดียวกัน

หน้า **เส้นทาง ระยะทาง ราคา** รวมข้อมูล 4 ชุดที่เดิมแยกกันอยู่ 4 sheet
ไว้ในแถวเดียวกัน — 1 แถว = 1 เส้นทาง ต่อ 1 ประเภทรถ
เพราะทั้งสี่อย่างผูกกับ "เส้นทาง + ประเภทรถ" เหมือนกันหมด

ระยะทางกรอกเป็น **ขาเดียว** เสมอ ขากลับต้องเพิ่มเป็นอีกแถว เพื่อกันการกรอกผิดเป็นไป-กลับ

การตั้งราคา 22 ช่วงราคาน้ำมัน × 2 ชุด (ลูกค้า/รถร่วม) มีเครื่องมือช่วย:
กรอกราคาช่วงเดียวแล้วกด "เติมให้ทุกช่วง" ระบบไล่ราคาขั้นบันไดให้ หรือคัดลอกทั้งชุดจากเส้นทางอื่น

### 2. เกณฑ์ราคาน้ำมันของลูกค้า ตั้งเป็นสูตรได้เอง

ลูกค้าแต่ละรายตกลงวิธีคิดราคาน้ำมันไว้ไม่เหมือนกัน ระบบจึงเก็บเป็น "สูตร" ที่แก้ได้
ไม่ใช่ตัวเลือกตายตัว — เพิ่มแบบใหม่ได้เองที่หน้า *ตั้งค่า → เกณฑ์ราคาน้ำมันลูกค้า*

| ชนิดสูตร | ใช้กับ |
|---|---|
| `SHIP_DATE` | ราคา ณ วันที่ขนจริง |
| `DAY_OF_MONTH` | ราคาวันที่ N ของเดือน (วันที่ 1, วันที่ 25, …) |
| `SEMI_MONTHLY` | วันที่ 1-15 ใช้ราคาวันที่ 1 / วันที่ 16 เป็นต้นไปใช้ราคาวันที่ 16 |
| `AVERAGE` | เฉลี่ยช่วง `startDay`→`endDay` · ถ้า start > end คือคาบข้ามเดือน (16→15, 20→19) · `monthOffset` = ถอยหลังกี่เดือน |

ครอบคลุมทุกแบบที่บริษัทใช้อยู่: ราคาวันที่ 1 · ราคาวันที่ 25 · วันที่ 1 และ 16 ·
เฉลี่ย 16-15 ใช้เดือนถัดไป · เฉลี่ย 1-31 เดือนเดียวกัน · เฉลี่ย 20-19 ใช้เดือนถัดไป · ราคาวันขนส่ง

ราคาของวันที่ไม่มีประกาศ = ราคาประกาศล่าสุดก่อนหน้า จึงกรอกเฉพาะวันที่ราคาเปลี่ยนก็พอ

### 3. เงินพิเศษค่าน้ำมัน ไม่ต้องจับคู่เอง

เดิมต้องนั่งดูตารางว่า "ขาไป A + ขากลับ B = น้ำมัน X" แล้วจับคู่กับที่เติมจริงเอง
ตรวจสอบย้อนหลังไม่ได้

ระบบใช้ **รหัสรอบ** แทน: ทุกขาที่อยู่รอบเดียวกันใช้รหัสเดียวกัน
เป้าหมายน้ำมันของรอบ = ผลรวมของ (ระยะทาง ÷ อัตราสิ้นเปลืองเป้าหมาย) ของทุกขาในรอบ
แล้วเทียบกับลิตรที่เติมจริงในวันจบรอบ

```
เงินซื้อคืน = (เป้าหมายรอบ − ลิตรที่เติมจริง) × อัตราซื้อคืน
ใช้เกินเป้า → ได้ 0 บาท แต่ไม่หักเงิน
```

รายงานแสดงเส้นทางทุกขาในรอบพร้อมเป้าหมายรายขา จึงตรวจย้อนกลับได้ทุกตัวเลข
ถ้าเติมคนละวันกับวันจบรอบ แก้ลิตรจริงในตารางได้ทันที

### 4. ตัวเลขทุกรายงานมาจากเครื่องคำนวณตัวเดียว

`src/lib/calc.ts` คำนวณรายขาเพียงที่เดียว แล้วรายงานทุกหน้าใช้ผลลัพธ์ก้อนเดียวกัน
จึงไม่มีทางที่ตัวเลขสองหน้าจะขัดกันเอง

มีสคริปต์ตรวจความสอดคล้องให้รันได้ตลอด:

```bash
npx tsx scripts/verify-consistency.ts   # ตรวจว่ารายงานทุกหน้าตัวเลขตรงกัน
npx tsx scripts/verify-calc.ts          # ดูรายละเอียดการคำนวณทีละขั้น
```

ตรวจว่า: รายงานค่าใช้จ่าย (ทั้ง 4 มุมมอง) รวมเท่ากับต้นทุนในงบกำไรขาดทุน ·
รายงานรายได้ (ทั้ง 4 มุมมอง) รวมเท่ากับรายได้ในงบ · กำไรรายคันรวมกับค่าใช้จ่ายส่วนกลาง
เท่ากับกำไรสุทธิ · เบี้ยเลี้ยงงวด 1 + งวด 2 เท่ากับทั้งเดือน

### 5. รถร่วมไม่ถูกนับต้นทุนซ้ำ

ค่าน้ำมันและค่าใช้จ่ายที่บริษัทออกแทนรถร่วม จะถูกหักคืนตอนจ่ายค่าจ้างอยู่แล้ว
ระบบจึงไม่นับซ้ำเป็นต้นทุนบริษัท — ต้นทุนของงานรถร่วมคือ "ค่าจ้างรถร่วม" ก้อนเดียว
(ถ้านับซ้ำ ต้นทุนจะสูงเกินจริงและกำไรจะดูต่ำกว่าความเป็นจริง)

### 6. บอกทันทีเมื่อข้อมูลยังไม่ครบ

ทุกขาที่คำนวณไม่ได้จะถูกทำเครื่องหมายพร้อมบอกสาเหตุ (ไม่พบเส้นทาง / ยังไม่ตั้งราคาช่วงนี้ /
ไม่พบการจับคู่ พขร. / คิดต่อตันแต่ไม่ได้กรอกน้ำหนัก) แสดงทั้งที่หน้าหลักและหน้าบันทึกงาน
เพื่อไม่ให้เผลอเชื่อรายงานที่ตัวเลขยังไม่ครบ

```

src/lib/reports.ts        รายงานทุกตัว (ใช้ผลจาก calc.ts)
src/lib/crud.ts           นิยามหน้าจัดการข้อมูล — เพิ่มตารางใหม่ = เพิ่ม config หนึ่งก้อน
src/lib/fuel-import.ts    รูปแบบไฟล์นำเข้าการเติมน้ำมัน
src/lib/date.ts           วันที่ (รองรับ พ.ศ. และ ค.ศ.)

src/app/entry/            หน้าบันทึกประจำวัน
src/app/reports/          หน้ารายงาน
src/app/db/               หน้าฐานข้อมูล
src/app/stock/            หน้าคลังอะไหล่
src/app/settings/         หน้าตั้งค่า
```

**เพิ่มรูปแบบไฟล์น้ำมันใหม่:** เพิ่ม config ใน `LAYOUTS` ที่ `src/lib/fuel-import.ts`
โดยระบุว่าคอลัมน์ไหนคืออะไร

**เพิ่มตารางฐานข้อมูลใหม่:** เพิ่ม model ใน `schema.prisma` + เพิ่ม config ใน `RESOURCES`
ที่ `src/lib/crud.ts` + สร้างไฟล์ `page.tsx` 6 บรรทัด

## หมายเหตุเรื่องข้อมูลที่นำเข้ามา

- **วันที่แบบ พ.ศ.** ในไฟล์เดิม (เช่น `31/03/2570`) ถูกแปลงเป็น ค.ศ. อัตโนมัติ
- **ทะเบียนรถ** ในไฟล์เดิมเขียนไม่เหมือนกันทุกที่ (`70-1779` กับ `70-1779 ลบ.`)
  ระบบตัดคำต่อท้ายให้เหลือเลขทะเบียนล้วน เพื่อให้จับคู่กันได้
- **ลูกค้าที่ไม่มีรหัสย่อ** ในไฟล์เดิม ระบบตั้งรหัสให้ชั่วคราวเป็น `C001`, `C002`, …
  ควรเข้าไปแก้ให้เป็นรหัสจริงที่หน้าข้อมูลลูกค้า
- **เส้นทางในไฟล์เดิมมี 4 เส้นทาง** และเป็นประเภทรถ `รถพ่วง` ซึ่งไม่ตรงกับประเภทรถจริง
  ในทะเบียนรถ (`รถดั๊ม`, `หัวลาก`, …) — ต้องเพิ่มเส้นทางจริงให้ครบก่อนใช้งาน
  ไม่งั้นงานจะขึ้นเตือนว่า "ไม่พบเส้นทาง"
- **พขร. บางคน** ที่มีในตารางจับคู่รถแต่ไม่มีในทะเบียนพนักงาน ถูกสร้างให้เป็น `(รอกรอกชื่อ)`
